# 落地解决方案 v0.4

日期：2026-10-26。状态：方案设计，待实现与验证。

本方案放在“设计推导”之后，以用户提供的 [原架构图](../WechatIMG85.jpg) 为基础，保留三层纵深防御和 Agent Loop 双插件结构。环境边界分析继续使用 [v0.2模型](environment-boundaries.md)。风险尚未评分，本方案是候选实施架构，最终范围与优先级待实际评估确认。

## 方案主链路

用户／任务身份 → Agent运行时双插件 → 授权判定 → 工具执行代理 → 沙箱／业务资源。

管理面维护身份、准入、策略、凭据与审计。任务执行身份无权改变自身约束。模型输出和风险检测结果交给执行层处理，实际资源访问必须受执行层约束；只接入提示词或回调不能证明不可绕过。

## 原图三层对应的实现

| 层 | 组件 | 自身实现或部署职责 | 既有软件依赖 |
|---|---|---|---|
| 外层 | EDR／IOA适配器 | 关联任务与终端事件；产品支持时调用响应接口 | 终端检测、隔离等依赖对应产品能力，未接入不提供等价能力 |
| 外层 | 资源访问网关 | 受控模型、MCP与API出口；目标和服务身份检查及审计 | 可接零信任网关，需检查是否覆盖全部实际路径 |
| 外层 | 数据外发控制 | 对受控模型请求和工具输出执行规则、脱敏及接收方限制 | 办公通道可接EDLP；日志、遥测和自定义API另行覆盖 |
| 中层 | 工具代理与受限执行器 | 按任务校验文件、网络、命令、设备权限；凭据代理；限制旁路 | 必须依托OS、隔离运行环境或业务服务授权能力 |
| 中层 | Skill准入 | 来源、版本、完整性、权限声明、扫描、受控发布 | 可用企业制品和审批系统；准入不代替运行权限控制 |
| 中层 | Agent准入与任务授权 | 绑定用户、租户、Agent、服务身份；权限到期、吊销和委派收敛 | 可对接企业身份系统，仍需实现任务级授权关联 |
| 内层 | 数据与凭据防泄漏插件 | 检查上下文、模型请求、工具参数、结果与持久化内容 | 复杂识别可以集成外部能力，需记录可用性及检测边界 |
| 内层 | 运行时风险拦截插件 | 结合来源、风险信号及授权输出允许、拒绝或待确认 | 语义检测不能独自承担资源隔离或不可绕过保证 |

## 六阶段实施动作

1. 会话装配：加载经过准入的Skill与配置；隔离任务和租户状态；记录来源及版本。
2. 用户输入：识别主体并建立任务授权；附件和引用内容不能授予新的执行权限。
3. LLM请求：检查数据与目标端点，按策略脱敏或阻断，记录实际发送范围。
4. 工具执行：绑定任务、动作、对象、参数与执行身份；必要时确认具体操作，再交由受限执行器执行。检查与执行之间不能允许参数被替换。
5. 回调／跨Agent：校验来源，委派权限收敛，状态回写按租户和任务校验，子任务共享预算。
6. 输出／持久化：检查接收方、敏感信息和状态归属；覆盖输出、日志、记忆与缓存。

关联任务ID、调用ID、执行身份、策略版本、判定与实际结果。审计自身需要访问控制、保留策略及敏感内容处理。

## 部署方式

- 个人计算机：本地Agent接入双插件，工具代理与受限身份执行文件、网络和命令操作；浏览器会话单独授权；按已有条件对接IOA、EDR和办公DLP。
- 服务器：租户、任务、工作负载和服务身份分别绑定；网关及工具服务执行授权，工作负载隔离，状态和队列保持租户归属；凭据代理、共享预算和幂等控制。
- 有OS的物联网设备：可部署本地执行代理，限制驱动和设备接口；远程指令在设备端校验。
- MCU或单地址空间固件：复杂策略可放在边缘网关，设备端保留指令校验、限值及必要保护。不能据此声称MCU具备独立沙箱；网关不能替代设备物理保护。

可信基础须明确包括宿主、管理面、隔离机制和业务授权服务；其失陷后的保证需另行评估。故障时按动作类型定义拒绝、暂停或安全降级，物理设备必须考虑停止本身是否安全。

## 分阶段交付与验收

| 阶段 | 交付范围 | 验收重点 |
|---|---|---|
| 一期：基础执行闭环 | 选一个可接入Agent；身份、工具代理、受限执行、出口规则、审计 | 超范围文件访问、上传及直接网络旁路被拒绝；检查实际副作用 |
| 二期：双插件与准入 | 六阶段接入、数据检查、Skill清单、确认与吊销 | 注入诱导外传、未准入Skill、确认后改参数、授权到期 |
| 三期：集成与环境扩展 | 接入已有安全软件；服务器多租户或设备执行适配 | 联动覆盖、租户隔离、重试幂等、设备断网和限值 |

无既有安全软件时只承诺自身控制覆盖的能力，明确不提供EDR等价检测；接入后的增量保证通过对应接口与攻击路径验证，不能由产品名称推断。
