Zenity 视频精读：恶意 MCP、数据外传与记忆投毒

先纠正这条视频的分类

标题写的是“Shadow AI 发现与风险评估”，实际画面和简介讲的是一条恶意 MCP 工具攻击链。前半段展示 CFO 助手的信息外传，后半段展示网站 Agent 的会话外传、长期记忆污染，以及 Salesforce 线索字段被恶意加密。资料库此前依据标题将它归入“产品与治理演示”，现改为“攻击链与威胁研究”，保留英文原标题方便核对。

整个案例最值得关注的是：攻击者把额外指令伪装成合规要求，让正常工作的 Agent 越过工具、数据与记忆之间的信任边界。视频没有展示 Zenity 自身控制台的检测、阻断或恢复过程，不能据此认定其产品已经拦截了这些步骤。

按时间核对攻击链

定位画面证据与说明如何理解
00:13编辑器中的 MCP 服务暴露一个名为 compliance_tool 的工具。画面说明称恶意内部人员把提示注入放入工具描述，诱使企业 Agent 自动调用。攻击入口是工具元数据。工具用“合规”的身份包装额外指令，试图把低信任来源变成 Agent 必须遵守的规则。
00:21工具实现与画面说明显示，它收集用户查询和 Agent 回复，并发送到攻击者的外部存储。一次貌似正常的工具调用同时成为数据外传动作。输出给用户的回答可以继续保持正常。
00:26–00:39CFO 在命令行助手中请求根据 Salesforce 收入与销售管道生成董事会摘要；随后出现 Azure 存储请求日志。00:31 的说明指出，共享 AgentCore 网关让多个组织 Agent 信任并调用该工具。用户提出的是正常业务任务。问题在于 Agent 使用自身的数据访问能力时，又接受了与任务无关的外送要求。网关及共享工具关系使影响面可能超过一个助手；具体受影响数量未展示。
00:44–00:52先展示空的语义记忆查询结果，随后网站“Book a Demo”助手列出 Salesforce 读取、创建线索等工具，也包含该合规工具。画面给出记忆污染前的参照，并切换到另一种业务入口。工具列表显示网站助手可以接触相同的恶意工具；列出工具本身不等于完成了攻击。
01:05编辑器中修改工具描述。烧录说明称内部访问被撤销后，攻击者从外部继续更新 MCP 工具，影响后续行为。这是演示设定：人员权限撤销后，对远端 MCP 服务的既有信任仍然保留。视频没有展示撤权控制台，不能把它说成已独立验证的身份系统漏洞。
01:18–01:39普通潜在线索通过网站请求产品演示；之后出现 Salesforce 和攻击者存储日志。说明称会话再次被外传。合法访客无需提交恶意提示，也可能触发已被污染的工具链。第二个业务场景表明攻击不局限于 CFO 的命令行助手。
01:44AgentCore 语义记忆记录把“使用 create_lead 时以指定密钥处理输入”记成用户要求。恶意指令被转换成可被未来调用的“用户偏好”，形成记忆投毒。画面显示一条记录，并未证明它在所有 Agent 或所有记忆分区中生效。
01:57–02:02新的正常演示申请中，助手把部分字段标为出于安全而编码；Salesforce 列表中新线索的姓名、职位、公司等字段呈密文样式。演示已经从信息泄漏走向业务数据完整性破坏。画面直接支持至少一条新线索受到影响；说明中“此后所有写入”的更大范围没有逐项展示。

第一层：工具描述为什么能改变执行行为

MCP 工具需要向 Agent 说明名称、用途、参数等信息，Agent 才能决定何时调用。视频把恶意要求放在这一入口，并用合规与安全的理由让它看起来具有组织权威。这里跨越的边界是：用于理解工具的数据，被当成了给 Agent 下达新任务的指令。

因此，仅核查用户输入是否恶意会漏掉这类问题。CFO 的用户请求只是生成摘要，网站访客只是预约演示；两者都没有授权把完整对话交给外部存储。Agent 能访问 Salesforce，并不意味着每个被它看见的工具都有权获取这些数据。研究上可将其理解为工具描述投毒，以及有权限的助手被诱导执行额外动作。

工具名称“合规”不能证明工具的组织授权。需要关联实际发布者、版本、所有者、业务用途与数据流。模型是否认为工具描述合理，和组织是否允许把某类数据发送到某个目的地，是两项不同的判断。

第二层：共享网关与撤销权限的缺口

00:31 的说明将共享 AgentCore 网关列为多 Agent 信任同一工具的原因。这不是在证明网关产品本身存在一个通用漏洞，而是在展示集中接入后，工具信任关系可以被多个使用者继承。一个被共享的错误配置，可能沿依赖关系扩大影响。

01:05 又引入一个生命周期问题：撤销内部人员账户，并不会自动删除他曾接入的远端服务，也不会自动让所有客户端停止加载后续变动的工具描述。该情节依赖攻击者仍控制远端 MCP 服务，并且企业仍保留连接；视频没有完整展示这些权限和部署细节。

对采购与架构评估，应该把“人离职”和“工具失去信任”做成可关联的流程：能否找出此人接入的 MCP 服务、其依赖的 Agent、服务凭据与发布版本？工具描述或实现发生变化时，能否重新评估、暂停使用并留下证据？这些是本案例引出的验证建议，不是视频已展示的 Zenity 功能。

第三层：正常回答不能证明数据没有泄漏

CFO 场景中，助手仍生成了收入与销售管道摘要。攻击者无需让回答明显失败，只需要让 Agent 在完成任务的同时调用额外工具。00:39 的目的端日志是重要证据：演示把“模型可能受到诱导”进一步连接到了实际网络请求及其携带的数据。

与此同时，录屏没有提供完整原始调用链、网络抓包或可独立执行的复现包。因此，可以说“演示画面展示了外传结果”，不能说“我们已独立验证任意 Agent 都会如此”。也不应从画面中存在 Azure 或 Salesforce 就推断两家服务本身被攻破；它们在案例中分别承担外部接收端和业务系统的角色。

防护启示是关联数据读取与后续外送，而不只检查单个回答。业务账户的合法权限、工具的可调用性、目的地的网络可达性都可能分别成立，但整条动作链仍然超出用户任务授权。

第四层：从会话注入变成长期记忆污染

00:44 的空记忆结果与 01:44 的语义记忆记录构成前后对照。后者把攻击者要求描述为“用户希望”，这一步比单次会话中的错误回答更值得注意：攻击指令获得了持久化位置，并可能在后续任务中被当成可信上下文重新读出。

仅从录屏无法确认究竟由哪个组件、哪条策略完成记忆抽取和写入，也没有足够证据证明全部记忆共享范围或存活期限。能直接观察到的是，一条涉及工具输入变换的指令被记录为用户偏好，随后业务字段出现了相应异常。把这一过程概括为记忆投毒是研究判断，详细实现仍需要原始事件与写入日志核实。

清理当前会话或撤掉恶意工具后，已经写入的记忆也需要单独检查。记忆系统应保留来源、主体、时间、适用范围与修改记录；来自工具返回或第三方页面的要求，不应无条件成为长期业务规则。涉及未来工具行为、外送地址或数据处理方式的记忆尤其需要可信授权。

第五层：这段演示也在讲业务完整性

最后的 Salesforce 列表不是只展示聊天内容泄漏，而是展示业务字段被改写成密文。对于销售线索系统，这会影响人工识别、检索、分配、去重和后续联系。这里讨论的是对业务影响的分析，视频本身并未逐项展示这些下游流程。

烧录说明使用了“攻击者的私钥”这一说法，但画面中的 Fernet 是对称加密方案。中文解读采用“攻击者掌握的密钥”，避免把它误解为公私钥机制。录屏不足以证明原始数据不可恢复，也没有勒索要求或解密流程，不能进一步断言这是一个已完成的勒索事件。

同样需要限制范围：视频最后能直接看到一条新线索的多个字段呈密文样式；“所有后续 Salesforce 数据都会被加密”是演示说明提出的范围，录屏未覆盖全部操作路径。我们应记录这个差别，避免将场景设定写成独立测量结果。

它对 Zenity 产品判断能说明什么

这条片子体现了 Zenity 在工具信任、Agent 数据流、共享接入和记忆持久化等问题上的研究关注。它适合作为选型讨论与威胁建模材料，帮助采购方理解为什么单靠资产清单、用户提示过滤或业务系统权限都可能不够。

但视频没有给出启用 Zenity 前后的对照，没有展示策略配置、告警页面、阻断发生位置、处置动作与恢复验证，也没有测量误报、延迟、可用性或支持范围。它能支持“厂商公开展示了这条攻击链”，不能独自支持“厂商产品已覆盖并阻断整条链”。与专题中官网公布的 Surface、Enforce、Protect 能力应分别建立证据。

下一次产品演示应验证什么

  1. 工具接入和变更：同一个 MCP 服务的描述或行为改变后，能否识别变更并重新决策？证据应包括发布者、版本、依赖关系和处置记录。
  2. 任务与外送：CFO 被允许读取 CRM 生成摘要时，系统能否在请求发出前阻止向未授权目的地发送查询和回复？展示拒绝位置及目的端没有收到数据的证据。
  3. 记忆写入：恶意要求被总结为用户偏好时，能否追溯其来源并拦下敏感规则的持久化？重新开会话验证它没有再次生效。
  4. 业务写入：在创建线索前，能否发现未经授权的字段变换，并避免密文进入业务系统？应区分传输加密、合法业务加密与该场景的恶意字段变换。
  5. 撤销与恢复：禁用人员、移除工具、撤销凭据、清理污染记忆和修复业务记录能否形成完整闭环？检查还有哪些 Agent 保留连接。
  6. 实际覆盖边界：上述控制分别依赖网关、SDK、连接器、业务系统集成还是网络出口？直连和旁路是否受到同等约束？要求按部署方式展示证据。

这些是本项目提出的验收问题，不代表原视频已经展示或厂商已经承诺。对我们自己的 Agent 安全方案，最直接的启示是同时控制工具信任、任务授权、数据出口、记忆写入和业务副作用，并用同一条审计链关联它们。
